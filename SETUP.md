| Output | What it is |
|---|---|
| `hero/deadlift/flex.jpg` | Optimised artwork |
| `*-depth.jpg` | Derived depth maps — these drive the parallax |
| `banner.webp` | The animated 3D banner, 16 warped frames |
| `banner.jpg` | Static first frame |
| `plates.jpg` | The three plates as 3D perspective cards |
| `cards/<repo>.webp` | One animated output card per project, 30 frames |
| `cards/<repo>.jpg` | Final frame of each, static fallback |

### The portrait

Source is your existing `assets/img/profile.JPG` — the script reads it straight
from the repo, so nothing new was added. It is a casual selfie in a restaurant,
which would fight the ink theme untouched, so `ink_portrait()` grades it the same
way the drawings are graded: greyscale, local contrast, an S-curve onto the
bone/void ramp, then a **centrality-weighted depth map darkens the background to
near-black**. That is what removes the restaurant without any masking by hand.

Two constants near the top of `build_assets.py` control framing, both expressed
as fractions of the source frame so they survive a different photo:

- `CARD_CROP` — 4:5, head and shoulders, for the site
- `AVATAR_CROP` — 1:1, hair down to below the chin, for the README

**Swapping in a new photo:** drop it at `assets/img/profile.JPG`, re-tune those
two boxes, and rerun. If the new photo is not a centred head-and-shoulders shot,
also widen the ellipse in `portrait_depth()` — that is what decides which part of
the frame survives.

### Card resolution

Scenes are written against a 640×360 coordinate space, but export at **1024×576**
(`EXPORT = 1.6` in `build_project_cards.py`). That is deliberate: the site renders
a card at roughly 500 CSS px, and a 1.5× or 2× display then needs 750–1000 device
pixels. Exporting at 640 meant every 9px label got upscaled and went soft.

Raise `EXPORT` if you want them sharper on a 2× display in the README too — it
costs file size roughly with the square of the number. `SS` is the supersample
factor used for antialiasing before the downsample; leave it at 3.

### About the numbers on the project cards

**Every figure drawn on a card is copied from that repo's own README.** Nothing is
estimated, illustrative, or rounded up in your favour — the chest-xray card reads
`0.9587`, not `0.96`, and its axis starts at 0.90 and says so on the card.

If you re-measure something, edit the literal in that `scene_*` function in
`tools/build_project_cards.py` and rebuild. Source values sit at the top of each.

**`llm-serving-unit-economics` is not included.** The URL 404s and it is not in

## Tuning the banner

`banner.webp` is 746 KB — the cost of 16 full photographic frames. Knobs at the
top of `build_assets.py`:

- `FRAMES` / `QUALITY` — the two that actually move file size
- `AMP_X`, `AMP_Y` — how far the parallax swings, in pixels
- `BSCALE` — export scale. Layout is written in an 890×276 design space; this
  only changes the resolution it is written out at.

### Why BSCALE is 1.0, and not higher

890px is GitHub's README render width, so the banner is sharp at 1× and gets
upscaled on a 2× display. Raising `BSCALE` fixes that. Measured cost:

| BSCALE | pixels | frames | quality | size |
|---|---|---|---|---|
| **1.00** | 890×276 | 16 | 72 | **746 KB** |
| 1.35 | 1202×373 | 16 | 68 | 1234 KB |
| 1.50 | 1335×414 | 16 | 66 | 1430 KB |
| 1.50 | 1335×414 | 14 | 62 | 1195 KB |

Raising quality instead does **not** help — it reduces compression artefacts,
which are already fine at 72, but cannot add resolution.

It stays at 1.0 because the only soft element is 48px display type, which
degrades gracefully, and the design already carries deliberate scanlines and
grain — mild softness reads as print texture rather than as a defect. Paying
+488 KB to sharpen decoration, on a README that already loads 1.36 MB, is a bad
trade for readers on mobile.

If you disagree, it is a one-line change: set `BSCALE = 1.35` and rebuild.

Want it lighter instead? Point the README's first image at `3d/assets/banner.jpg`
(84 KB, static). Everything else still works.

## How the 3D works

There is no 3D library. `3d/index.html` ships a hand-written WebGL shader:

1. A depth map is derived from each drawing — dense cross-hatching marks the
   figure, mid-grey marks skin against blown-out or solid-black background, and
   the subject occupies the centre. Those three cues get blended and smoothed.
2. The plate is a real quad in a perspective projection that tilts toward your
   pointer, or the gyroscope on a phone.
3. The fragment shader walks that depth map and offsets each pixel along the
   view direction — two-step offset mapping — so near ink travels further than
   far ink. That is the pop.

The README banner is the same effect pre-warped to frames, because GitHub serves
README images through a proxy with a strict CSP that can block scripts and
`data:` URIs inside an SVG. Frames always render.
